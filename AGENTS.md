# Astra agent rules: XGBA emulator fork

## Start here on every new chat

1. Read [docs/NEXT_ASTRA_HANDOFF.md](docs/NEXT_ASTRA_HANDOFF.md), then the companion game [DevElectrum/xgba-emerald-test](https://github.com/DevElectrum/xgba-emerald-test) `AGENTS.md`, `docs/NEXT_ASTRA_HANDOFF.md`, and `docs/XGBA_E6_PLAN.md` (on `xgba/e5-expanded-save` until E6 branches exist). Inspect actual branch HEAD and latest CI before changing anything. No assumptions from stale historical notes.
2. This is a **personal passion project**, not a company release. The user wants **Regieleki speed**: ambitious leaps, rapid fixes and a few useful smoke tests, not a hundred risk gates. Keep a recoverable known-good branch and save copies, but never bog down work with exhaustive testing.
3. E5 **accepted**: `xgba/e5-save-expansion` maps a separately initialized **1 MiB** `.sav` with native Flash1M unchanged at its original first 128 KiB, and a persistent 896 KiB experimental extension exposed at CPU addresses starting `0x0F000000`. User successfully wrote and audited independent snapshots in Worlds 3 and 20, saved, exited XGBA, restarted, and verified both. This does **not** prove full game saves, giant boxes or a 16 MiB extension.
4. E6 **planned, not yet implemented**: explore a **16 MiB versioned save format**, independent world progression/parties/Pokémon storage and ~100 boxes/world as a stretch target alongside gameplay restored in 20 Hoenns. See companion repo `docs/XGBA_E6_PLAN.md`; respect 0x0F addressing bounds, existing 0x0E flash semantics, RTC trailer, explicit migration and protection of proven E5 save. When implementing, create experimental emulator branch `xgba/e6-large-save` from E5. Do not claim that branch exists before creating it.
5. Preserve `master` and the accepted E5 branch. Never touch `DevElectrum/grand-anthology` during these experiments. Do not commit ROM images, user saves or copyrighted binaries. Prefer commits on experiment branches.
6. **Required durable checkpoints:** after each meaningful implementation milestone, test, blocker or architectural pivot, update `docs/NEXT_ASTRA_HANDOFF.md` and, when practices change, this `AGENTS.md`. Also update companion game's handoff and E6 plan if its next steps or interfaces change. Record exact commit, branch, changed files, CI URL/status, user-tested vs untested results, failure and the next action. Commit before conversation ends or length becomes risky.
7. User wants **almost always three terminal commands**: (1) update/build, (2) copy/migrate save if needed, (3) launch Qt `mgba-qt` with ROM. If save migration isn't needed, give two. Never imply a remote GitHub commit has already updated their local Nyx checkout; they must `git pull`.
8. Use the user's tested Qt GUI path `~/Projects/xgba/build-xgba-gui/qt/mgba-qt`. Local project sibling: `~/Projects/xgba-emerald-test`. Provide safe commands that do not overwrite verified saves.
